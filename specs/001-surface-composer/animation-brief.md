# Animation Brief — UIKit Surface Composer

**Feature:** `001-surface-composer`
**Project:** `examples/surface-composer`
**Role:** Motion grammar for a Telegram Mini App demo that sells `tg-mini-app-uikit` through premium feel, system continuity, and interaction trust.
**Scope:** US1 `First launch` + US2 `Range remix`, with hooks for US3–US6.
**Decision:** First increment is **no-WebGL by default**. The product must feel alive because the UIKit surface is alive, not because a separate renderer is impressive.

---

## 1. Animation intent

Animation must make the Mini App feel:

- **Generated by a system**, not manually mocked.
- **Telegram-native**, not a web landing page inside a phone frame.
- **Tactile**, with feedback anchored to the exact touch point.
- **Composed from reusable UIKit primitives**, even before technical proof is shown.
- **Responsive under pressure**, absorbing safe area, theme, viewport, haptic, keyboard, and fallback changes without panic.

The first emotional read should be:

> “It noticed me. It knows where I touched. The surface is one living object. This could be my product.”

The second read, after touch:

> “This is not a video. This is a system I can build on.”

---

## 2. Motion principles

### 2.1 Origin-first

Everything important must be traceable to one continuity object: the seed / origin point.

The origin:

- births the surface;
- sends out token and safe-area rails;
- becomes the contact marker under the user’s first touch;
- anchors US2 remix;
- carries through later proof and receipt scenes.

No scene may feel like a new page loaded.

### 2.2 Contact-first

Primary feedback must start at the user’s contact point, not at the center of the component.

For every tap:

```ts
contact = { x: event.clientX, y: event.clientY }
originPulse(contact, responsibleElement)
radialHighlight(contact)
recorder.log({ source, target, reaction, status })
```

The UI should communicate: “I know exactly where you touched.”

### 2.3 Continuity over transition

Remix is not navigation. Remix is one object changing business language.

Allowed:

- shared element motion;
- FLIP translate + scale;
- local rotation around seed axis;
- preserved safe-area rails;
- persistent selected context and runtime mark.

Banned:

- page cross-fade;
- tabbar transition;
- hard remount;
- five static screenshots;
- a carousel that looks like a portfolio gallery.

### 2.4 Quiet by default

The product should not constantly perform. Idle motion must be almost invisible.

Default idle:

```css
.surface[data-motion-state="idle"] {
  transform: scale(1.004);
}
```

Only the surface breathes. Text, icons, proof badges, and cards do not shimmer.

### 2.5 Honest capability states

Native, mock, and browser fallback states must be visually different.

- Native: stable, confirmed, low-noise.
- Mock: visible but not pretending to be native.
- Fallback: explicit and reversible.

Never fake device vibration or native Telegram capability.

### 2.6 Reduced motion is a designed state

Reduced motion is not “turn animations off”. It is a static choreography:

- origin mark visible;
- rails already resolved;
- same content order;
- same recorder events;
- no looping motion;
- no long-path travel, rotation, depth, or refraction dependency.

## 3. Motion system layers

| Layer | Purpose | Motion style |
|---|---|---|
| Stage | Cinematic contrast around phone | Very slow light falloff, no looping spectacle |
| Phone shell | Telegram WebView container | Subtle settle, no bounce |
| Surface | Living product object | Birth, idle breathing, pressure absorption |
| Origin / seed | Continuity object | Pulse, rail emission, touch anchor |
| Components | UIKit proof in use | FLIP resolve, contact reaction, focus response |
| Runtime | Telegram constraints | Squeeze, remap, mirror, fallback state |
| Proof layer | Engineer trust after buyer cares | Sheet rise, pins, layer isolation |

## 5. Motion tokens

Use semantic local tokens for the demo; map them to existing UIKit timing where possible.

```css
:root {
  --sc-duration-instant: 80ms;
  --sc-duration-fast: 140ms;
  --sc-duration-touch: 180ms;
  --sc-duration-panel: 280ms;
  --sc-duration-remix: 620ms;
  --sc-duration-birth: 920ms;

  --sc-ease-out-expo: cubic-bezier(0.16, 1, 0.3, 1);
  --sc-ease-out-quint: cubic-bezier(0.23, 1, 0.32, 1);
  --sc-ease-functional: cubic-bezier(0.2, 0, 0, 1);
  --sc-ease-pressure: cubic-bezier(0.34, 0.8, 0.18, 1);

  --sc-origin-x: 50%;
  --sc-origin-y: 50%;
  --sc-contact-x: 50%;
  --sc-contact-y: 50%;
  --sc-motion-intensity: 1;
}
```

Avoid elastic spring bounce. Premium here is inevitability, not play-toy physics.

## 6. US1 choreography — Birth

| Phase | Time | Visual | Technical method | Meaning |
|---|---:|---|---|---|
| Seed breath | 0–180ms | Accent point wakes up | `scale`, opacity, radial glow | Product has an origin |
| Rails emit | 120–340ms | Safe-area and token rails grow from seed | SVG lines or pseudo-elements, `scaleX/Y` | System constraints appear |
| Surface ghost | 260–460ms | Phone surface gains depth | opacity + `scale(0.985→1)` | Telegram surface arrives |
| Components resolve | 340–760ms | Header, chips, preview, proof strip, CTA land | FLIP translate + scale | UIKit primitives assemble |
| Light sweep | 760–920ms | One committed accent sweep | masked gradient | Signature moment closes |
| Idle | 920ms+ | Surface breathes once, then rests | `scale(1→1.004)` | Alive, not noisy |

Rules:

- Copy may become fully readable only after the component has resolved.
- No uniform fade-in.
- No full-screen particle field.
- Rails must map to real layout / token / safe-area ideas.
- The CTA must feel like it was assembled, not merely displayed.

## 7. US2 choreography — Remix

US2 must prove that one surface speaks many businesses.

```ts
type BusinessContext = 'shop' | 'booking' | 'wallet' | 'support' | 'community';
```

Remix order:

```text
shop → booking → wallet → support → community
```

Motion sequence:

| Phase | Visual | Meaning |
|---|---|---|
| `remix-start` | Surface compresses to `0.992`; seed brightens | The object is preparing to change |
| `separating` | Header/media/metric/action/list detach by 4–8px | Slots are reusable |
| `rotating` | Slots rotate around seed axis with slight perspective | Same system, new business |
| `recomposing` | New content inherits old bounds | No page reset |
| `locked` | Primary action updates in place | Context changed |
| `continuity` | tokens / safe area / theme / runtime marks remain anchored | The system persisted |

Reduced-motion version:

- no rotation;
- two-step content replacement;
- continuity marks remain visible;
- same recorder events are emitted.

## 8. Interaction grammar

### 8.1 Tap on primary target

Visual response must start within 100ms.

```text
touch down → contact light → element pressure → action preview → recorder tick → settled state
```

Use:

- local scale: `0.985–0.995`, never rubber bounce;
- radial highlight from `--sc-contact-x/y`;
- short origin pulse to responsible element;
- visible recorder tick only after proof layer is available.

### 8.2 Tap on empty space

Empty space must acknowledge recognition without destructive action.

Pattern:

```text
soft contact ring → nearby rails barely glow → no state change → optional “recognized” recorder event
```

This creates the “what else can I tap?” feeling without turning the interface into a toy.

### 8.3 Long press

Long press reveals structure, not random explosions.

Pattern:

```text
press hold 420ms → element lifts 2px → surface dims 4% → local layer split → labels attach to real UI
```

Use for:

- product preview card;
- CTA;
- proof strip;
- context switcher.

### 8.4 Drag / gyroscope

Drag is only for US2 remix exploration.

- Horizontal drag controls context proximity.
- On release, nearest context locks.
- Seed remains visually stable.
- Do not let drag become a free carousel.

### 8.5 Keyboard focus

Focus must feel designed, not default browser residue.

Pattern:

```text
focus visible → inner accent ring resolves from nearest corner → same proof path as pointer
```

No clipped focus rings.

### 8.6 Loading

Skeletons must read as construction rails, not generic shimmer.

- Use short rail reveal.
- No infinite shimmer.
- Loading settles into real component positions.

### 8.7 Error / blocked state

Error must be alive and reversible.

Pattern:

```text
surface lowers intensity → affected slot marks blocked → fallback action appears → recorder marks fallback
```

No red panic banners unless the scenario is destructive.

## 9. Component-specific animation behavior

### Context chips

- Active chip contains the accent.
- Tap emits a contact light from the tapped coordinate.
- Selected state slides from old chip to new chip through shared element transform.
- Long labels must compress through typography, not clipping.

### Live preview card

- On tap: contact highlight follows image bounds.
- On long press: media, title, price/metric, CTA, and proof row split into named slots.
- On drag: slight parallax via CSS perspective, not WebGL.

### Primary CTA

- Press: `scale(0.992)` + contact glow.
- Release: action text and icon align toward the next scene.
- If MainButton is simulated, mirror state is shown honestly after proof layer is available.

### Buyer-proof strip

- Avatars / proof pills respond as a group.
- Tap reveals trust meaning, not raw test vocabulary in first viewport.
- After first touch, proof can expose `native | mock | fallback` status.

### Inspector sheet

- Opens from the first contact point, then resolves as a bottom sheet.
- Back / Escape closes it before scene navigation.
- Pins attach to real surface elements.

## 10. No-WebGL implementation strategy

The desired “alive” effect can be built with DOM, CSS, SVG, and a small rAF layer:

| Desired effect | No-WebGL method |
|---|---|
| 3D depth | CSS `perspective`, `translate3d`, shadow parallax |
| Touch light | CSS radial gradients with `--sc-contact-x/y` |
| Shader-like glow | masked pseudo-element, `mix-blend-mode` used carefully |
| Rails | SVG lines or absolutely positioned pseudo-elements |
| Morphing slots | FLIP measurements + transform |
| Origin pulse | radial mask + SVG path stroke dashoffset |
| Runtime pressure | CSS variables for insets / viewport / theme |
| Layer split | duplicate DOM snapshots or structured slot transforms |

WebGL may be considered later only for a **stage-only atmospheric layer**, never for the live UIKit surface. The live surface must remain inspectable, accessible, and testable DOM.

## 11. Instrumentation

Every visible motion must produce or be associated with a recorder event.

```ts
type RecorderEvent = {
  id: string;
  scene: string;
  source: 'pointer' | 'keyboard' | 'runtime' | 'system';
  target: string;
  reaction: string;
  status: 'native' | 'mock' | 'fallback';
  motionState: string;
  businessContext?: string;
  timestamp: number;
};
```

Examples:

```ts
recorder.log({
  source: 'pointer',
  target: 'surface.preview.media',
  reaction: 'contact-highlight+inspector-open',
  status: 'mock',
  motionState: 'first-touch',
});
```

## 12. Performance and quality gates

Mandatory gates:

- no long task over 50ms during signature sequences;
- 60fps target on reference preview;
- first visual response within 100ms;
- no layout-property animation;
- no overlap at 320 / 375 / 430 / desktop;
- RTL and long Russian labels tested;
- reduced motion path emits same recorder events;
- visual snapshots at key states:
  - `seed`;
  - `rails`;
  - `assembling`;
  - `idle`;
  - `first-touch`;
  - `remix-start`;
  - `separating`;
  - `rotating`;
  - `locked`.

## 13. Animation acceptance test

Hide all text. A reviewer should still understand:

1. a system generated the surface;
2. the origin point matters;
3. the surface responds to touch;
4. the same object can become different businesses;
5. Telegram constraints are being absorbed, not ignored.

If this fails, the animation is decorative, not product animation.
