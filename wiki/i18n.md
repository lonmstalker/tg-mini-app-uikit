# i18n / localization


**Summary**: The kit is fully localizable through `TKLocaleProvider`; the
[[trailhead-demo]] must ship complete Russian and English with zero hardcoded
user-facing strings.
**Status**: verified (kit); policy set (demo)
**Updated**: 2026-06-14

---

## Kit mechanism

- `packages/uikit/src/foundation/i18n.tsx` defines the `TKLocale` interface (every
  user-facing string the kit renders) with English defaults. Resolution order is
  component prop → `TKLocaleProvider` value → English defaults, so the kit works
  with no provider and is fully localizable without a fork.
- Templated strings use `{placeholders}` resolved by `tkFormat`.

## Demo policy (hard requirement)

- The demo is fully bilingual **Russian + English, no exceptions**. Every
  user-facing string — including kit strings via a `TKLocale` for each language —
  is localized. No literal user-facing text in components.
- Dictionaries live in `examples/trailhead/src/i18n/` as typed `en.ts` and `ru.ts`
  sharing one key type, so a missing key in either language is a TYPE error.
- The active language follows the Telegram client language when available and is
  switchable in Platform Lab (Profile tab); the choice persists via
  `useDeviceStorage`.
- Both Russian and English are LTR, so RTL is exercised separately as a kit stress,
  not required by the demo content.

## Verification

- A unit test asserts `en.ts` and `ru.ts` have identical key sets (no gaps).
- An e2e/visual pass renders every screen in both languages; see
  [[testing-and-review]]. A lint/test fails on hardcoded user-facing strings.
