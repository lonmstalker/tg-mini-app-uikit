# Current Platform Research Protocol

Use this reference when the request needs current product category evidence, competitor pattern synthesis, or modern UI/UX conventions.

## Domain First

Identify the product category before researching references. Classify the project as specifically as possible: fintech, developer tools, AI productivity, CRM, healthcare, education, e-commerce, analytics, collaboration, project management, creator tools, marketplaces, cybersecurity, HR tech, legal tech, real estate, travel, logistics, social/community, B2B SaaS, or another precise domain.

If the domain is unclear and guessing would change the recommendation, ask one concise clarifying question. If enough context exists, state the assumption and proceed.

## Allowed Evidence

Prefer current, product-contextual sources:

- official product websites;
- live or recently updated landing pages;
- public product demos;
- onboarding flows;
- current documentation;
- help centers;
- changelogs;
- release notes;
- current app store listings;
- official web app screenshots;
- design system documentation;
- dated public case studies;
- recent product update announcements;
- current competitor feature pages.

## Disallowed Primary Evidence

Do not use these as primary evidence:

- old screenshot dumps;
- generic UI inspiration collections;
- recycled SaaS screenshot libraries;
- outdated design trend articles;
- Dribbble or Pinterest boards;
- non-current "best UI examples" posts;
- visual galleries without dates or product context;
- isolated marketing images detached from real product flows.

## Recency Validation

Treat a platform or pattern as current only when there is a recency signal, such as:

- visible publish or update date;
- recent changelog or release note;
- app store version history;
- current docs page;
- current pricing or feature page;
- recent official product announcement;
- active public demo or onboarding surface;
- dated case study that still maps to the current product.

If browsing or external research is unavailable, say so explicitly and ask the user for recent reference products, screenshots, links, or competitor names. Do not invent current research.

## Synthesis Rules

Research approaches, not visuals to copy.

Extract:

- onboarding structure;
- navigation model;
- dashboard hierarchy;
- information density;
- empty-state strategy;
- search and filtering behavior;
- settings organization;
- user role and permission flows;
- collaboration patterns;
- notification design;
- AI interaction patterns;
- pricing and upgrade prompts;
- trust and security signals;
- data visualization style;
- mobile vs desktop behavior;
- accessibility considerations;
- tone of voice;
- progressive disclosure;
- form design;
- error handling;
- loading states;
- command palette usage;
- personalization;
- workspace/project/account switching;
- audit/history/activity feeds.

Avoid copying:

- exact layouts;
- visual identity;
- proprietary UI;
- icons;
- illustrations;
- copywriting;
- unique competitor-specific interactions.
